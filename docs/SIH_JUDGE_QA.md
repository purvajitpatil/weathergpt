# SIH Judge Q&A — Honest Answers

## Where does your weather data come from?

**Live mode:** [Open-Meteo](https://open-meteo.com/) — GFS/ICON-based numerical weather prediction, no API key required. Air quality from Open-Meteo Air Quality API. Geocoding from Open-Meteo Geocoding API.

**Demo mode:** Deterministic fixtures in `/demo/weatherFixture.ts`, clearly labeled with `isDemo: true` and UI DEMO badge.

**We do NOT use IMD observational data directly.**

## What exactly does AI do?

Gemini (via LLM Gateway) provides:
- Natural language explanation of structured evidence
- Multilingual response generation (en, hi, mr, and architecture for more)
- Conversational interaction and follow-up suggestions

Gemini does **NOT** determine weather values, warnings, or agricultural decisions.

Simple queries (current temperature, AQI) skip the LLM entirely.

## What exactly does ML do?

XGBoost classifier predicts rain risk probability from 14 weather features. Integrated into the Risk Engine as one input alongside rule thresholds and official alert severity.

**Training data:** Synthetic by default (`ml/train.py`). This is a demonstration pipeline, not production meteorological intelligence.

## How do you prevent hallucinations?

1. Evidence layer — LLM receives structured evidence, not raw authority
2. Deterministic short-circuit for simple queries
3. Safety validator with 6 layers including demo mislabel detection
4. Schema validation on all LLM output
5. Grounded fallback when LLM fails or safety rejects

## How do you validate warnings?

- Alert ingestion pipeline: schema validation → normalization → deduplication
- Expiry enforced at query time (`expiresAt > now`)
- Severity normalization (green/yellow/orange/red)
- Location matching via affected areas/districts

## What happens if the weather provider goes down?

- `DEMO_MODE=auto`: falls back to demo fixtures with honest labeling
- `DEMO_MODE=off`: returns error, never fabricates weather
- Cached data served from Redis when available

## What happens if Gemini goes down?

Deterministic answers from weather engine + evidence. Chat still works without AI narration.

## How do you scale during a cyclone?

- Redis caching (300s weather, 900s forecast) — many users hitting same city share cache
- Intent-based tool routing — not every request calls LLM
- Rate limiting per IP via Redis

## Why should users use this instead of a weather app?

WeatherGPT adds:
- Conversational multilingual queries ("उद्या पुण्यात संध्याकाळी पाऊस पडेल का?")
- Evidence-grounded explanations with recommendations
- Agriculture decision support with rule engine
- Location-aware disaster intelligence architecture
- Voice accessibility (browser Web Speech API)

## What is your innovation?

Evidence-grounded AI architecture where deterministic engines own truth and LLM owns explanation — designed for Indian multilingual, agriculture, and disaster use cases.

## How does agriculture reasoning work?

Rule engine (`AgricultureAdvisoryEngine`) combines:
- Crop + stage (from `crops.json`)
- Current weather + forecast
- Rain probability thresholds
- Irrigation context

Output: action, reasonCodes, riskLevel, evidence. LLM explains the recommendation.

## What data trained the model?

Synthetic data generated by heuristic rules in `ml/train.py`. Evaluation report in `docs/ml_evaluation_report.json` (after running `npm run evaluate`).

## How was ML evaluated?

ROC-AUC, PR-AUC, F1, Brier score, calibration. Quality gates: ROC-AUC ≥ 0.65, F1 ≥ 0.55. Compared against baseline classifier.

## What is your source provenance?

Every weather observation carries `provenance`: provider, sourceLabel, retrievedAt, validFrom, validUntil, isDemo. Frontend displays "Updated X minutes ago" and LIVE/DEMO badge.

## How do you handle multilingual voice?

Browser Web Speech API for ASR. Language set per user selection (en-IN, hi-IN, mr-IN). Server-side transcription returns 501 (not implemented). TTS via browser speechSynthesis.
